# Security review — AI Compartment Studio backend (Ladder 1), 2026-11

Scope: `worker/**` (router, auth, every handler), `shared/contracts.js`, `shared/validation.js`, `shared/scene-spec.js` +
`shared/lib/prompt.js` (prompt construction), `processor/**`, `public/_headers`, `worker/wrangler.toml`,
`docs/architecture/ai-compartment-studio.md` (§3 auth, §5 storage, §8 spend, §15 payloads), `docs/audit/worker-security.md`.
Reviewer model: Claude Sonnet 5.5 (adversarial pass by a reviewer that did not write the code).
Evidence: every defense below is exercised by a test in `worker/test/security/**` (Vitest, real router + handlers + `node:sqlite`
D1/R2 fakes, only `fetch`/JWKS mocked) or `processor/test/security.test.js` (`node --test`, real api-client/adapter/job-runner against
`node:http` mocks). The fixes were verified by reverting `worker/src` + `processor/src` and observing 27 + 4 of the new tests fail.

## Threat model

| Attacker | Capability | What we defend |
|---|---|---|
| Internet anonymous | browser, curl, any Origin/headers, the public repo | every non-public route 401; public routes expose only public + committed display/thumb images; no write path on `*.workers.dev` |
| Malicious web page | cross-site POST/PUT/DELETE riding a signed-in editor's cookie | Origin allow-list + Fetch Metadata check before authentication |
| Valid MBFD editor (insider / compromised account) | any editor API with a valid Access JWT | no admin routes, no processor routes, owner-bound upload/commit/cancel/retry, spend caps, server-built prompts, magic-byte + size + pixel validation, cannot influence model/quality/size |
| Stolen processor service token | all `/api/processor/*` | cannot reach user/admin routes; lease-bound per job; cost/usage/ids/outputs validated and capped; no ability to call OpenAI (key lives on the node only) |
| Compromised processor node | OpenAI key + token | bounded: cannot requeue a paid job from `saving`, cost capped at 5x reservation, output type/size/pixels checked, provider text never shown to users |
| Operator-authored text | tool names, descriptions, titles, instructions reaching the image prompt | quoted block for instructions; single-line flattening for every other interpolated field |

Trust assumptions: Cloudflare Access edge enforces the Access policy and signs JWTs; the Worker re-verifies them. `editor` = any
valid user JWT (architecture §3), so editors share one workspace by design: any editor can read/modify committed assets, mounts,
designs and links. Only upload/commit (asset creator), cancel/retry (job requester) and admin routes are owner/role-bound.

## Findings, ranked

Severity = impact if exploited in the intended deployment. "Fixed" = code change + regression test in this change set.

### High

**S-01 Lease check skipped on raw processor endpoints.** `GET /api/processor/assets/:id/:variant` and `PUT .../output/:variant`
took the node from `X-L1-Node`/`?node=`; when omitted, `node` was `null` and `leasedJob` skipped the lease-owner comparison. Any
holder of a service token could read the reference photos of, or write result images into, any in-flight job without owning its
lease. Fix: the node is mandatory (400 otherwise, max 64 chars) in `worker/src/processor.js` `nodeHint`.
Tests: `processor-api.test.js` "raw endpoints refuse requests that name no node at all", "another node cannot heartbeat, upload,
complete, fail or read assets…", "after the lease expires and another node re-claims…". Residual: all nodes share one service token,
so node names are self-asserted; a hostile node that knows another node's name and a job id can still impersonate it (job ids are
unguessable and only the leaseholder sees them). Per-node tokens would remove this (see lead items).

**S-02 `AUTH_MODE=test` honored unless ENVIRONMENT was literally `production`/`staging`.** A new environment block that forgot
`ENVIRONMENT`, `"Production"`, `" staging"`, or an empty value left the whole API open to `X-Test-Actor: user:x@y,admin`. Fix: an
allow-list — test mode only when ENVIRONMENT is `test`, `development` or `local` (`worker/src/auth.js`). Tests: `auth.test.js`
"AUTH_MODE=test can never be honored outside test/development/local" (7 environment values x user/service x 3 route classes) and the
`wrangler.toml` assertion (no `AUTH_MODE=test` anywhere; production + staging pin `access`).

### Medium

**S-03 Public endpoint served the full-size original.** `setMainImage` makes an asset public; `/api/public/assets/:id/original`
then served the 25 MB camera file (EXIF/GPS, unresized) to anonymous callers. Fix: public variants are display/thumb only
(`assets.getPublicVariant`). Test: "a public asset serves display/thumb but never the full-size original".

**S-04 No pixel/dimension limit on uploads or processor output.** Magic-byte sniffing read the dimensions but nothing capped them:
a few header bytes declaring 30000x30000 were stored and later decoded by the browser/`sharp`. Fix: `withinPixelLimits` — uploads
<= 4096 per edge and 16.7 MP, processor output <= 8192 per edge and 36 MP (`worker/src/media.js`, used by `putVariant` and
`putOutput`). Tests: PNG/JPEG/WebP bombs, 20000x1 edge case, 4096x4096 accepted, processor output bombs. Residual: the processor's
`sharp` also enforces `limitInputPixels: 120M`; HEIC/other formats are refused before storage.

**S-05 Prompt-section injection through operator-authored names.** Instructions are safely quoted (`>>>` defused, control chars
stripped), but tool names/descriptions/dimensions (planner ops accept newlines, 300/2000 chars), mount names/descriptions and photo
titles are interpolated as list items. `"Halligan Bar\n\n8. NEW RULES ..."` created a fake numbered section outside the quoted block;
recognition catalogue names with `\neq_x: Admin Key` could forge catalogue lines on the processor side. Fix:
`neutralizeSpecText`/`flatText` in `worker/src/studio/job-spec.js` collapse control characters in every interpolated field (and the
recognition registry/labels) before the prompt is built; fingerprints still use the raw doc, so staleness is unaffected. Tests:
`spend-and-prompt.test.js` "prompt injection stays quoted data" (6 tests: instructions closing the block, fake sections, house style
position, control characters, tool names/descriptions/dimensions, mounts/titles, recognize catalogue). Residual: a hostile name can
still say things on its own *single* line of the tool list ("Axe — ignore the list above"); the prompt's "do not add equipment not
listed" and the human review of every draft are the remaining controls. Operators cannot reach `style.houseText` (admin-only).

**S-06 Cost reported by the processor was unbounded.** `complete` accepted usage-derived cost or an `actualCostUsd` hint with only
`>= 0`/finite checks: a stolen token could settle a job at $1e9 (monthly budget exhausted: denial of the Studio) or, with negative
tokens, fall back unpredictably. Fix: `costOf` caps at `max(5 x reservation, $0.25)`; usage > 4 KB, non-string request ids and
out-of-range dimensions are not stored. Tests: "reported cost stays within [0, 5x reservation]" x6, "oversized or non-object usage".
Residual: nothing prevents under-reporting (cost 0 with a hint and no usage) — requires a compromised processor and only affects
accounting accuracy, never spend (the OpenAI key is on the node).

**S-07 Provider error text relayed to users.** `fail` stored the processor-supplied `message` (up to 300 chars) as the user-visible
`error_message` for every code except a few lower-case OpenAI codes that the processor never sends (it sends `PROVIDER_*`), and the
processor itself forwarded the sanitized OpenAI `error.message` (can contain key fragments, org ids, prompt excerpts). Fix, both
sides: processor `mapHttpError` emits fixed messages (the sanitized provider text stays only in the local log as `detail`), and
`humanFailure(code)` in the Worker returns fixed texts keyed by an allow-list of codes, generic text otherwise. Tests: worker
"a failure message from the processor … is never echoed to users", processor "provider error bodies … never reach the Worker report",
"mapHttpError: every status produces a fixed, provider-text-free message".

**S-08 Processor client followed redirects with Access secret headers; downloads were not restricted to asset endpoints.** Node
`fetch` forwards custom headers (`CF-Access-Client-Secret`) across redirects; a compromised/misconfigured Worker route could bounce
the credentials to any host, and a claim's reference URL could target any same-origin API path with the service token. Fix:
`redirect: 'error'` on every call (the health probe keeps `manual`), downloads restricted to `/api/processor/assets/` on the Worker
origin (`processor/src/api-client.js`). Tests: "a redirect from the Worker origin is never followed", "download only fetches processor
asset endpoints … (SSRF via a claimed reference url)" (17 hostile URLs, 0 requests made), "a claim whose reference URL points at a
foreign host fails the job without contacting that host".

### Low

- **S-09 CSRF relied on the Origin header alone.** Added Fetch Metadata: a mutating request without Origin but with
  `Sec-Fetch-Site: cross-site|same-site` is refused (`router.js`). Tests: foreign / `null` / look-alike Origins on 5 mutations with a
  valid cookie, and the Fetch-Metadata case. Residual: relies on Access cookies being `SameSite` and browsers sending Origin.
- **S-10 `Idempotency-Key` on `retry` was not length/shape validated** (only create was). Now shares `idempotencyKey()`.
- **S-11 Response hardening.** Added `Strict-Transport-Security` to all Worker responses; image responses now carry
  `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; sandbox`, `Content-Disposition: inline`, and an allow-list of
  servable content types (anything else, e.g. tampered R2 metadata, is `application/octet-stream`). Tests: "every kind of API
  response carries …", "a JPEG with trailing script is served as inert image/jpeg", "the served Content-Type comes from the
  verified bytes".
- **S-12 Any Access service token of the application counted as the processor.** Added optional `PROCESSOR_SERVICE_IDS`
  (comma list of Access client ids; unset keeps current behaviour). Test: "PROCESSOR_SERVICE_IDS pins which service tokens count".
  **Needs a `wrangler.toml` var (lead item).**
- **S-13 JWKS: stale keys stay usable while the certs endpoint is unreachable** (`getVerifyKey` falls back to the cached key after a
  failed refresh). A rotated-out/revoked key therefore validates until the next successful fetch. Accepted (availability during an
  Access outage; Access tokens are short-lived). Not changed. Failure behaviour for an unknown kid while the endpoint fails is fail
  closed with a generic 401 (tested).
- **S-14 R2 overwrite race in `putVariant`.** The R2 `put` happens before the D1 `WHERE status='pending'` update, so a PUT racing the
  commit of the same asset by the same owner (or an admin) can overwrite committed bytes under the same key. The actor is already
  entitled to delete that asset, so impact is nil beyond the editor's own content. Not changed.
- **S-15 `style-src 'unsafe-inline'`** is required by React style attributes. Scripts remain `'self'` + Insights only. Accepted.
- **S-16 No rate limiting on editor endpoints** other than the spend ledger and size caps. Behind Access (MBFD identities only), so
  accepted; a Cloudflare rate-limiting rule on `/api/*` would be defense in depth (lead item).

### Info / verified clean

- **JWT**: alg `none`, HS256 signed with the public modulus, attacker key + known `kid`, unknown `kid`, URL/path/`__proto__` kids,
  expired, future `nbf`, wrong issuer, wrong/absent/empty `aud`, missing/non-numeric `exp`, `aud` arrays — all rejected (generic 401, no
  detail). Only the configured `<team>/cdn-cgi/access/certs` URL is ever fetched. Unset/placeholder `ACCESS_AUD`, missing team
  domain, unknown `AUTH_MODE` fail closed. Header beats cookie; an invalid header is not rescued by a valid cookie; look-alike cookie
  names are ignored.
- **Routes**: `ROUTES` is enumerated programmatically — anonymous gets 401 on every non-public route in both auth modes; service
  identities get 403 on every editor/admin route; editors 403 on every service and admin route; wrong methods 405 with `Allow`.
- **Open redirect** `/api/auth/login?return=`: 19 hostile values (`//x`, `/\x`, `\\x`, absolute URLs, `javascript:`, `data:`,
  single/double-encoded, CRLF, tab, NUL, leading space) all land on `/` or a same-origin path.
- **IDOR / object access**: upload/commit owner-bound; cancel/retry requester-bound; mount links, asset links, main image,
  job references and recognize subjects cannot cross compartments; private/pending/deleted assets are indistinguishable from unknown
  ids on the public endpoint; R2 keys are `assets/<compartment>/<asset id>/<variant>.<sniffed ext>` built from ids and the sniffed
  type only (traversal ids never reach R2; `compartmentId` is an allow-list).
- **Stored XSS**: HTML/SVG/GIF/`text/html`-declared uploads are rejected (415) by magic bytes whatever the declared type; polyglot
  JPEG+script is stored but served inert.
- **Size limits**: bodies without Content-Length and with lying Content-Length are cut at the byte limit while streaming.
- **Legacy `*.workers.dev` host**: no `/api` routes (404 even with a test-actor header), `PUT/POST` answer 409 `APP_UPDATED`/403, DB
  and R2 untouched. Its read-only GET `/state` and `/images` remain anonymous (the two `WS-02` `test.fails` in `worker/audit.test.js`
  intentionally still document this; the same data is public via `/api/public/*`).
- **Spend**: tampered bodies (model/quality/size/cost/prompt/`__proto__`/preset names/verify kind) rejected with nothing reserved;
  model/quality/size come only from admin presets; instructions capped at 2000 chars, bodies at 1 MB; idempotency keys are
  per-user and compartment-bound; parallel requests respect per-user concurrency; retries reserve once and obey caps; recognize
  jobs are metered; AI-disabled refuses; OUTCOME_UNKNOWN is settled at the estimate, failed, and never reclaimed (repeated
  recovery and claims); a processor cannot requeue a job from `saving`; ledger amounts are always >= 0.
- **Processor**: logs never contain Access secrets, OpenAI keys, auth headers, data URLs, base64 runs or bytes (including nested
  errors); all calls have timeouts (api 30 s, upload/download 120 s, OpenAI 300 s → `PROVIDER_TIMEOUT`, outcome unknown, not
  retryable); downloads are size-capped even with chunked/lying lengths.
- **Headers**: `public/_headers` CSP is self + `static.cloudflareinsights.com` (script) + `cloudflareinsights.com` (connect) + `data:`/`blob:`
  images, no `unsafe-eval`, no wildcard, `frame-ancestors 'none'`, `object-src 'none'`; `Permissions-Policy` grants only `camera=(self)`;
  HSTS 1 year + includeSubDomains; the app has exactly one module script, no inline script/handler, no `eval`/`new Function`, and no
  third-party origin (`headers-config.test.js`). API responses carry nosniff, no-referrer, `X-Frame-Options: DENY`, no-store, HSTS, CSP.
- **Secrets**: `git log -p --all` (31 commits) scanned for OpenAI/AWS/GitHub/Slack key shapes, PEM blocks, Access client ids and
  JWTs: **no hits** other than the synthetic `SECRETS` fixture in `processor/test/support/helpers.js`. The working tree is checked by
  `headers-config.test.js`. `worker/wrangler.toml` commits identifiers only (account id, KV/D1 ids, Access AUD tags — not secrets).
- **HEIC under this CSP**: `heic2any` bundles an Emscripten build that calls `new Function`, which the CSP (correctly) blocks;
  `src/lib/image/decode.js` catches it and shows the existing "could not be converted on this device" message (iOS "Most Compatible"
  /JPEG uploads are unaffected). Functional note for the UI owner, not a vulnerability; do **not** add `unsafe-eval`.

## What was NOT verified

- **Real Cloudflare Access edge behaviour**: JWT issuance, the actual team certs endpoint, Access policies, the bypass application,
  cookie attributes, service-token handling, WAF/rate limiting. JWTs in tests are minted with local RSA keys and a mocked JWKS fetch.
- **Real OpenAI**: actual error bodies, moderation behaviour, output dimensions and billing; the processor was exercised against
  `node:http` stand-ins. The 8192-edge output cap is an assumption about current model output sizes (<= 4096 today).
- **workerd runtime**: tests run on Node with fakes, so Worker CPU/memory limits, real D1 batch/transaction semantics under
  contention and R2 consistency are modelled, not measured.
- **The React UI** (`src/**`): XSS handling of job errors, recognition labels and titles was not reviewed (React escapes by default).
- **Dependency vulnerabilities** (`npm audit`) — see WS-17 in `docs/audit/worker-security.md`; not re-run here (no network egress).
- **Production data/config**: D1/R2/KV contents, deployed secrets, the live Access AUD tag, the `workers.dev` hostname's real exposure.
