the items below it up, and removing an item from the inventory packs every compartment it was in. The server does the

and the Hub transfer key stay stable) and bundles follow their items; `removeCustomTool` and `setRemoved` pack the same
way. Slot count is unchanged (an empty slot is added at the end). Tabs opened before this release still blank the slot
until they reload; the next clear in a new tab packs again.

### Fix: edits made while a save is in flight were dropped (release fb8a5a9, Pages only)

Cause (a real sync bug from this branch's planner-sync engine, not a test problem): `send()` rebased the view onto the
server's answer without first queuing local edits whose 300 ms flush timer had not fired. A second edit made during a
save's round trip (another slot, a rename back, a removal) was silently dropped. Seen in a failure trace: the Remove
confirmation was accepted while a quantity edit was in flight, then the server's answer restored the item. `fetchRemote`
already flushed first (SD-18); `send()` now does too, on success and on failure.

- New `tests/app/planner-sync-inflight.test.js` drives the engine with a fake clock and API: second slot kept, rename
  back kept, newer edit kept when the in-flight entry is rejected. All three fail on the unfixed engine (with only the
  class exported) and pass with the fix.
- aiw-k8 (Tailscale): 1,009 unit tests, 145 of 145 browser tests, lint, audit, build. Stress (`--repeat-each 3`, whole
  suite): 0 sync or inventory failures in 2,610 runs (before the fix: 2-3 per 1,305). The remaining rare failures in
  stress were start-up timeouts spread across unrelated tests while aiw-k8 also ran two Hub CI VMs and another
  session's browser tests (load average 25-31 on 16 threads); the 240-run repeat of the one Excel-export failure passed.
- Released to staging, then production (Pages only; `shared/` and `worker/` unchanged since 45a6c11). Live planner
  unchanged (revision 28).
